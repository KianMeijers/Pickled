# Background jobs run on Procrastinate in a separate worker

Scheduled and background work (fetching Deals from each DealSource, drafting next week's Meal Plan) runs as Procrastinate jobs. Procrastinate keeps its queue in our existing Postgres database. The jobs run in a separate worker process (`pickled worker`), not inside the FastAPI app, so hot reload doesn't kill jobs and background agent runs don't slow down chat. We considered Celery, the most common choice in industry, and arq. We rejected both because they need Redis, which nothing else in the stack uses. Celery's async support is also clumsy for our async agent, and it doesn't yet list Python 3.14 support. We rejected APScheduler inside the app because it isn't a real queue and its jobs die whenever the app restarts. We also chose not to use durable execution (Temporal, DBOS): a failed job retries as a whole, and LangGraph's Postgres checkpointer can let a retried draft resume where it stopped. For a weekly job, that's enough.
