# Evals grade drafts with the plan summary code

Evals run the real agent on Runware against fixed scenarios and grade each finished draft. The checks code can make (hard failures such as an unfilled day, a repeated Recipe or a missed goal, and scores such as the share of shopping cost on Deals, perishable warnings and the distance from the nutrition target) reuse the same code that builds the plan summary the agent sees after every tool call (ADR 0007). They don't use a separate, independent grader. This means a bug in the plan summary can hide itself from evals: the agent and the grader would agree on the same wrong number. We accept that because the summary is the single source of truth for every calculated number. A second implementation would double the code and could drift from it, and the summary has its own deterministic unit tests. An LLM judge is used only where code can't decide: one yes/no per Taste note, one on variety, and one on whether a chat edit was carried out.
