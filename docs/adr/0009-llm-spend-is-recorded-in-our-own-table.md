# LLM spend is recorded in our own table

Every model call writes a row to our own `llm_call` table: the role, the model, what started the call (a job, or a Conversation and Meal Plan), the four kinds of token count, and a cost in USD. The cost is calculated from a price table in our code when the row is written. A callback handler inside `make_chat_model` writes the row (ADR 0004), so no call site can bypass it. This table is the record behind the monthly spend cap, which stops background LLM jobs when it is reached, and behind the spend shown in settings. We considered self-hosting Langfuse, which needs about five extra services in Compose for one user. We also considered LangSmith's cost tracking, an external free tier with short retention that we couldn't rely on to enforce a cap. Neither tool can fill in the cost itself, because Runware reports token usage but no cost (only the account balance, which we check daily). LangSmith is still available as an opt-in trace viewer, switched on by env var, but nothing depends on it. If our prices drift from Runware's real prices, the monthly comparison against the balance shows it.
