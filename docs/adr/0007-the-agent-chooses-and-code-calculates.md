# The agent chooses, and code calculates

When drafting and in chat, the agent makes the *choices*: the winning store, which Meals go on which day, and which Recipes to write or reuse. It makes them through thin tools over the domain modules. After every change, code rebuilds everything that can be calculated: the Shopping List, meal and shopping costs at both stores, Food Goal checks (nutrition against a 40% dinner share, vegetarian days, budget), perishable and store-split warnings, and rough-price counts. Code returns this as a short plan summary in the tool result. The agent never states a number it worked out itself. We considered letting the agent do everything (simple, but it makes up totals and can't be tested) and a fixed pipeline of LLM steps (predictable, but rigid in chat, where the Household changes one Meal at a time). This keeps the single `create_agent` loop from ADR 0004 with no `StateGraph`. A draft ends only when the agent calls `finish_draft`, which is allowed once every day has a Meal or has deliberately been left empty, within a limit of 40 model calls.
