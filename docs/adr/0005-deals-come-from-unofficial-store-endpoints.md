# Deals come from unofficial store endpoints, within a private-use budget

Neither Albert Heijn nor Jumbo has a public API, so Deals are read from endpoints the stores never offered for this. AH comes from the Appie mobile API (`api.ah.nl`, anonymous token). AH's terms allow personal use, but its app terms forbid reverse engineering; we only call endpoints already documented by open-source clients. Jumbo comes from the `__NUXT_DATA__` payload on `jumbo.com/aanbiedingen/nu`. Jumbo's terms forbid scraping and have no personal-use exception. We accept both risks because Pickled is a private tool for one Household. Hard rules follow from that: a realistic browser or app User-Agent, about 60 requests per store per week at most, counted and enforced in code (so we read listing pages and don't expand every promotion into its products), the data is never redistributed, and Pickled is never hosted for anyone outside the Household. The alternatives were AH only, which loses half the Deals, and paid aggregators, which are scrapers of the same pages with an extra middleman. **If Pickled ever serves other households, this decision has to be made again before launch.**

_Amended 2026-10-11 by "How are ingredients matched to Deals and prices?": the budget was raised from about 30 to about 60 requests per store per week, because AH Deals are fetched twice a week (~50) and AH price lookups need up to ~10 more. A per-store weekly counter in Postgres enforces it._
