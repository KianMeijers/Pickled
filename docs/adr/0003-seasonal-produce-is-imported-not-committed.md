# Seasonal Produce is imported into the database, not committed to the repo

Seasonal Produce comes from the Voedingscentrum seizoenskalender, the only usable Dutch source. Its terms allow personal, non-commercial use but forbid publishing a copy without written permission, and this repo is public. So the data never enters git: a committed command (`pickled seasonal import`) reads the calendar from the Voedingscentrum page's JSON-LD and loads it into Postgres on each machine, including any online deploy. The calendar doesn't say which produce is sold from storage, so a small committed file of our own lists the fresh-harvest months of storage crops (apples, onions, winter carrots and so on); the import tags an entry `stored` when its month falls outside that window. The import fails loudly rather than half-loading when the page changes, and the app still runs, without seasonal input, when no data has been loaded. Tests use a small made-up fixture. We considered asking Voedingscentrum for permission (blocks on a reply that may never come), a private data repo (a second repo to manage, unreadable from public CI), and writing our own list from several sources (more work and less authoritative).
